================================================================================
                            CUSTOM MODULE TUTORIAL
================================================================================

A module consists of three files:

    module.json      Hardware definition and MIDI/SysEx mappings
    layouts.json     UI layout
    dictionary.json  Enums, effect names and sound banks

Use the included modules as references and consult your synthesizer's MIDI
Implementation Chart or SysEx documentation whenever possible.

Notes
-----
• "address" is a continuous hexadecimal string (e.g. "01000005").
• "packet" and "data" are space-separated hexadecimal bytes.
• Packet placeholders are enclosed in [].
• Lookup names referenced in module.json must exist in dictionary.json.

================================================================================
MODULE.JSON
================================================================================

Root Properties
---------------

id              Unique internal identifier.
name            Display name.
manufacturer    MIDI manufacturer ID.
model           SysEx model ID.
device_id       Default SysEx device ID.
checksum        Checksum algorithm ("roland", "yamaha").
packet          Shared SysEx packet template.
header_length   Bytes before the address.
address_width   Address size in bytes.
mode            MIDI standard mode ("GS", "XG", "Native", "GM2").
detect          Auto-detection rules object (see Detection below).
objects         Array of parameters.

Packet Placeholders
-------------------

[DEVICE]
[MODEL]
[COMMAND]
[ADDRESS]
[DATA]
[CHECKSUM]
[VAL]

Default Supported Packet Formats
--------------------------------

Roland GS

F0 41 [DEVICE] [MODEL] [COMMAND] [ADDRESS] [DATA] [CHECKSUM] F7

Yamaha XG

F0 43 [DEVICE] [MODEL] [ADDRESS] [DATA] F7

Detection (Auto-Mode Switching)
-------------------------------

Used at the root level of module.json to identify standard/mode during stream scanning.

kind            Rule type ("sysex").
data            Single SysEx pattern string OR array of pattern strings.

--------------------------------------------------------------------------------
OBJECTS
--------------------------------------------------------------------------------

Every object requires:

id
kind

Supported kinds:

cc
pitchbend
patch
sysex

CC
--

cc              MIDI CC number.

Pitch Bend
----------

No additional properties.

Patch
-----

sequence        Message order (cc0, cc32, pc).
fields          Initial values (msb, lsb, program).
bank_select     Labels for MSB/LSB usage.
rhythm_channel  Default drum channel.
drum_msb        Drum bank MSB(s). Supports:
                - Single int: 127
                - Array: [104, 105, 106, 107]
                - Scalable range: {"start": 104, "end": 107}
sysex.base      Base address for SysEx patch selection.

SysEx
-----

address         Address inside a shared packet.

or

data            Complete standalone SysEx message.

Optional:

bytes           Data width.
encoding        Encoding ("nibbles").
lookup          Dictionary enum.
default         Initial value.
part_defaults   Map of per-part initial default values (e.g. {"10": 1}).
per_patch       Boolean (true if parameter resets per patch change).
display         UI formatting.

Display
-------

offset          Bipolar offset.
transform       Display conversion.

Supported transforms:

pan_lcr
pitchbend
frequency

Special Properties
------------------

controls_rhythm Marks a drum-mode assignment object.
parts           Per-channel SysEx address table. Supports:
                - Array of objects: [{"channel": 0, "address": "401000"}]
                - Scalable formula: {"base": "401000", "stride": "0100", "channels": [0,1,2]}

================================================================================
LAYOUTS.JSON
================================================================================

Defines only the user interface.

Variants
--------

full      Patches and parameters per channel, effects, system, widgets
compact   Patches and parameters per channel
tiny      Patches and volume bar per channel

================================================================================
DICTIONARY.JSON
================================================================================

Contains enums and sound banks.

Enums
-----

Every enum contains:

type
values

Supported entry fields:

id
name
short
short_name

Typical lookups:

reverb_types
chorus_types
delay_types
variation_types
efx_types
output_assign
efx_part_assign
part_mode

Banks
-----

Any top-level array is treated as a sound bank.

Bank properties:

id
name
selector

selector:

bank_msb
bank_lsb

Patch properties:

program
name

Optional:

bank_msb
bank_lsb
